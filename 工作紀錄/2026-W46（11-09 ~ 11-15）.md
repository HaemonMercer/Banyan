### 15:03 ~ 17:00 技術選型討論
| 主題 | 結論 |
|---|---|
| 前端框架 | 當時建議 Tauri 2 + Leptos（全 Rust）；之後文件改為 **TypeScript 的 React** |
| 資料儲存 | 建議 **SQLite**（`rusqlite`，`bundled`），全文搜尋用 FTS5；中文需用 `trigram` 斷詞或自訂斷詞 |
| redb vs SQLite | 仍選 SQLite；只有在「所有依賴都不能有 C」時才考慮 redb + Tantivy |
| Key-value vs SQL | SQL 先存資料再決定查法，KV 需先設計查法；筆記的關聯、標籤、階層較適合 SQL |
| 其他 SQL 資料庫 | 比較了 libSQL、Turso（純 Rust）、GlueSQL、DuckDB 等，嵌入式仍以 SQLite 最穩 |
| 技術缺口 | 內容資料模型（建議區塊樹）、同步策略（local-first / CRDT）、ID 格式（UUIDv7 / ULID）、附件以雜湊命名存放、編輯器實作方式 |
| 圖表渲染 | 預設 SVG，大量元素時改 Canvas |
